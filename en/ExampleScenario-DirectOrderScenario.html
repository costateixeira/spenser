ExampleScenario: Scenario - Ordering straight from the unit (Experimental)

Official URL: http://costateixeira.github.io/spenser/ExampleScenario/DirectOrderScenario Version: 1.0.0
Active as of 2026-11-13 Computable Name: DirectOrderScenario

A placer posts an order to a Spenser unit and gets back the dispense. No server, no Task, no tag: the POST is the authorization.

Actors

NameTypeDescription
Order Placer System

Whatever is asking for chocolate: a script, a client under development, or the unit's own dashboard.

Spenser Unit System

One dispenser, acting here only as a FHIR server.

Diagram

Processes

Process: Order a chocolate from the unit

One request, one chocolate.

Pre-conditions:

The unit is on the network and the placer can reach it. The lane for the code being ordered has stock.

Post-conditions:

A chocolate has been dispensed, and the unit holds a MedicationDispense recording it.

StepNameDescriptionInitiatorReceiverRequestResponse
1 POST /MedicationRequest - create (Details: FHIR Restful Interactions code create)

The unit dispenses before it answers. The response is 201 Created carrying the MedicationDispense, with a Location for the record the unit kept and an ETag. This changes the unit, so it needs the unit's key.

 Order Placer Spenser Unit The order The dispense

Alternative The lane is empty

Nothing moves, and the unit still answers with a MedicationDispense: status of declined, and notPerformedReason.concept of outofstock. A refusal is an answer, not an error.

Alternative The order asks for something the unit does not carry

The unit answers 400 with an OperationOutcome. Every error from a FHIR route on the unit is an OperationOutcome; there is no second error format.

2 GET /MedicationDispense - search-type (Details: FHIR Restful Interactions code search-type)

Optional, and open: reads need no key. The unit keeps what it dispensed, so the record can be read back later. The searchset also carries an entry with search.mode of outcome, saying when the unit last looked for work and how that went.

Instances

NameTypeContentDescription
The order SpenserRequest here

A MedicationRequest naming a chocolate from the IG's own code system. Neither the actionable tag nor a Task is needed on this route.

The dispense MedicationDispense here

What the unit returns, pointing back at the order in authorizingPrescription. An absent whenHandedOver means the unit's clock has not been set by NTP, not that the time is unknown.
